# UX-2 — Hero carousel spec drift

**Review date:** 2026-09-28  
**Project and baseline:** canonical `LonghornPublishers-CM`, `main` at `331c230`. Compared the current, uncommitted hero edits in `Docs/ui_ux_structure.md` (§4.2) and `Docs/wireframes.md` (§1 and §1.1) with `src/components/HeroCarousel.astro`, `src/lib/hero-carousel.ts`, and the homepage integration. This is a source review; no visual or assistive-technology acceptance pass was performed.

| Item | Spec value | Shipped value | Recommendation |
| --- | --- | --- | --- |
| Slide count and content source | Up to five enabled, ordered, admin-configurable slides, with localized content (`ui_ux_structure.md:65–67`). | `getHomepageHeroSlides()` selects enabled slides in sort order; CMS validation caps them at five. Development can fill to three local fixtures; production with no managed slides uses the static `Hero` (`cms-content.ts:236–263`, `index.astro:36–38,78–94`). | **Fix spec:** describe the 0/1/many slide states and development-only fixtures so the wireframe does not imply controls are always shown. No carousel code change. |
| Autoplay interval | 6000 ms per slide (`ui_ux_structure.md:72`; `wireframes.md:59,137`). | Default is 6000 ms; homepage passes the CMS setting; runtime clamps it to 3000–30000 ms (`HeroCarousel.astro:27–32`, `hero-carousel.ts:40`). Only a multi-slide carousel can advance. | **Fix spec:** state that 6000 ms is the default and an admin value may override it within the runtime range. Timing agrees at the default. |
| Progress placement and visible counter | A subtle **bottom-edge progress bar** and visible “Slide 1 of N” status beside dots (`wireframes.md:58–61`; `ui_ux_structure.md:72`). | Progress animates **inside the active dot**, not along the bottom edge (`HeroCarousel.astro:288–305`). The counter exists in markup but is hidden with `display: none` (`:106,267`). | **Fix code:** implement the specified bottom-edge progress and visible localized counter, or obtain an explicit UX approval to revise both specs to dot progress and no visible count. The current wireframe and shipped hierarchy are materially different. |
| Manual stop and resume | Prev/Next, dots, swipe, and Play/Pause stop autoplay for the session; only an explicit Play restarts it. Hover/focus and hidden-tab state pause temporarily and preserve remaining time (`hero-carousel.ts:82–92,130–201`). | **Fix spec:** qualify “permanent” as “until Play is selected” and include region arrow keys and hidden-tab pause. **Fix spec:** remove the literal `data-autoplay="false"` requirement in `wireframes.md:139`; the runtime uses `data-running`, `data-progress-paused`, and internal state. | Reduced motion | No autoplay; instant visibility change or subtle fade; no progress animation (`ui_ux_structure.md:83–84`; `wireframes.md:148–151`). | `matchMedia` gates autoplay, the Play toggle is disabled with a localized label, and CSS removes slide transitions and progress animation (`hero-carousel.ts:40–51,65–72,199–201`; `HeroCarousel.astro:323–328`). | ARIA and live announcement | Labelled carousel region; slides as groups; inactive slides hidden; polite announcement after manual slide changes (`ui_ux_structure.md:86`; `wireframes.md:153–157`). | These semantics are present only for multiple slides. The nested dot group repeats the region label rather than naming slide selection (`HeroCarousel.astro:107`). | **Fix code:** give the dot group a distinct localized label such as “Choose a slide”. **Fix spec:** document the single-slide omission, `inert`, `aria-current`, and quiet automatic advances. |
| Grid stacking and height | Stack all slides in one grid area to size for the tallest slide. Verify the longest approved French slide at narrow and short viewports before treating fit as accepted. |
| Optional-field omission | Eyebrow, accent, and the secondary CTA pair are optional; no empty element or gap when absent (`ui_ux_structure.md:67`; `wireframes.md:49–56,113–117`). | Eyebrow and accent render conditionally; secondary CTA renders only when both label and href exist. The component follows the intended omission rule. |
| Navigation placement | Prev/Next flank the hero near opposite edges; dots, counter, and toggle sit under the progress line (`wireframes.md:47–63`). | Prev, dots, Next, and toggle occupy one right-aligned bottom toolbar; the counter is hidden (`HeroCarousel.astro:102–129,227–240,267`). | **Fix code:** align controls with the wireframe hierarchy, subject to responsive and touch-target checks. If the bottom toolbar is the approved final layout, revise both wireframe views instead. |

## Handoff to Yv and SoSo

The main behavioral contract is implemented: the 6-second default, stop-after-manual-control policy, temporary focus/hover pause, reduced-motion gate, keyboard arrows, and manual live announcements. The visually meaningful mismatches are the progress/counter and navigation layout. The focusable region lacks a defined focus indicator. The height and padding numbers also differ substantially from the edited spec; those need a short-viewport and long-French-copy review before choosing final tokens.

The two edited spec documents and the component were left untouched. This report is the only file added in the canonical project. UX-2 remains in `review` for Yv's verification.
