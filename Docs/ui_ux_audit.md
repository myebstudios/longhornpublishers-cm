# UI/UX Audit — Longhorn Publishers Cameroon

**Date:** 2026-09-11
**Auditor:** Yv (CEO / Lead PM)
**Scope:** Public bilingual site (`src/pages/[lang]/`, `src/components/`, `src/styles/global.css`),
admin content workspace (`src/pages/admin/`, `src/layouts/AdminLayout.astro`), and the shipped
build in `dist/`.
**Method:** Source review + verification against built HTML output. Every P0/P1 below was
confirmed in `dist/`, not inferred from source.

---

## Verdict

The design system is genuinely good — considered type scale, coherent brand tokens, a real skip
link, `prefers-reduced-motion` handling, progressive-enhancement-safe scroll reveal. That
foundation is not the problem.

The problem is that **six of the seven public pages are static prototype HTML injected at build
time** (`src/components/PrototypePage.astro`), with French produced by exact-string find/replace.
The result: internal engineering notes, `Docs/README.md` references, and a developer `alert()`
are live on the production catalogue and contact pages. That is a credibility issue before it is
a usability issue, and it blocks launch.

**Launch readiness: NOT READY.** Clear P0 list, ~1 sprint of work.

---

## P0 — Blocks launch

### 1. Internal placeholder copy is live on production pages
`dist/en/catalogue/index.html`, `dist/fr/catalogue/index.html`, `dist/en/contact/index.html`

Visitors currently read:
> "Sample data — the live catalogue is populated from Netlify Database via the admin panel.
> A title list from the client is still outstanding (open item 4, `Docs/README.md`)."

> "Map placeholder — a branded embed replaces this in the Astro build."

A prospective institutional buyer sees us telling them our own project is unfinished, and sees a
path to our internal docs. **Remove before any external link is shared.**

### 2. "Load More" fires a developer `alert()` in production
`prototype/catalogue.html` → `dist/{en,fr}/catalogue/index.html`

```html
<button onclick="alert('Prototype only — pagination is wired to the database in the Astro build.')">Load More</button>
```
A primary CTA on the catalogue page opens a browser alert saying the site is a prototype. Either
wire real pagination or remove the button.

### 3. French pages silently fall back to English
`src/components/PrototypePage.astro:114-157`

French is generated by matching exact English strings against a hand-maintained pair list. Any
string not in that list ships untranslated. **Confirmed:** the "Sample data…" paragraph renders
in English on `/fr/catalogue/`. This is not a one-off bug — it is the architecture, and it will
keep producing new leaks every time copy changes. Bilingual parity is our core value
proposition; this undermines it structurally.

### 4. Focus indicator fails WCAG contrast
`src/styles/global.css:642`, `:596`, `:623`

`outline: 3px solid var(--green)` — `#6FBF3F` on white is **2.28:1**, below the 3:1 required by
WCAG 2.1 SC 1.4.11. Worse, `.field input:focus` and `.newsletter input:focus` set
`outline: none` and rely on a green border alone. Keyboard users cannot reliably see where they
are. Use `--green-deep` (`#2F7A2A`) or a burgundy ring, and never remove the outline without an
equally visible replacement.

### 5. Admin error messages render in green
`src/layouts/AdminLayout.astro` (`#status{color:var(--green)}`) + `src/pages/admin/news.astro`

`setStatus()` writes both "Article published." and "Unable to save article." into the same
`#status` element, which is unconditionally styled success-green. An editor whose save fails is
told so in the colour of success. Add `--ok` / `--err` states plus a non-colour cue (icon or
prefix) for colour-blind users.

### 6. No 404 page
`dist/404.html` does not exist. Any mistyped or stale URL — and we are publishing localised
slugs that will change — drops the visitor on Netlify's generic error page with no branding, no
navigation, and no language context.

## P1 — Fix before launch

### 7. Catalogue carousels are keyboard-inaccessible
`src/components/Carousel.astro`, `src/layouts/Layout.astro:151-173`

- `.carousel__viewport` is a scrollable region with no `tabindex="0"`, `role="region"`, or
  `aria-label` — fails WCAG 2.1.1. Keyboard-only users cannot reach cards beyond the first row.
- `prev.disabled = true` at scroll extremes **removes focus from a focused button**, dumping the
  user back to `<body>`. Use `aria-disabled` + a no-op handler instead.
- `scrollBy({ behavior: 'smooth' })` ignores `prefers-reduced-motion`.

### 8. Homepage hero image alt text is hardcoded English
`src/pages/[lang]/index.astro:87` — `alt="The Longhorn Publishers Cameroon team"` renders
identically on `/fr/`. Move to `src/i18n/{en,fr}.ts`.

### 9. Zero social / Open Graph metadata
`src/layouts/Layout.astro` has canonical, hreflang, and JSON-LD — all good — but **no `og:title`,
`og:description`, `og:image`, `twitter:card`, or `theme-color`.** Every share of this site on
WhatsApp, LinkedIn, or X — our actual distribution channels for institutional outreach — renders
as a bare grey link. High marketing cost, low engineering cost.

### 10. Images ship unoptimised with no layout reservation
`public/img/` holds three **2.1 MB PNGs** (`lh-editorial-team-wide.png`,
`lh-bilingual-editor-wide.png`, `lh-print-inspection-wide.png`) plus several 400–576 KB JPEGs.
No `width`/`height`, `loading="lazy"`, `decoding="async"`, or `srcset` anywhere in `src/`.

Consequences: cumulative layout shift on every page, and a first-load cost that is punishing on
the mobile networks most of our Cameroonian and DRC audience uses. Route through Netlify Image
CDN and convert the PNGs to WebP/AVIF.

### 11. Admin: double-submit and lost-work risks
`src/pages/admin/news.astro`, `src/pages/admin/catalogue.astro`

- Submit button is never disabled during `fetch` → double-click creates duplicate articles.
- `edit()` overwrites an in-progress form with no unsaved-changes guard.
- Repeated "Edit"/"Delete" buttons carry no article name in their accessible name — a screen
  reader hears ten identical "Delete" buttons.
- The article list shows `headline_en` only; a French-first editor has no view of their own work.

### 12. Admin UI flashes before the auth redirect
`src/layouts/AdminLayout.astro` — the role check `await getUser()` runs after render, so
unauthenticated visitors briefly see the full admin chrome before being redirected.

### 13. Mobile navigation is incomplete
`src/layouts/Layout.astro:102-127`

Escape-to-close and focus restoration are correctly implemented — credit where due. Missing:
body scroll lock while open, close on outside click, and reset when the viewport crosses the
1080px breakpoint (menu stays in the open state on rotate).

## P2 — Quality and consistency

### 14. Catalogue filters have no semantics or empty state
`src/layouts/Layout.astro:175-212` — `.chip` filters lack `aria-pressed` / radiogroup roles and
arrow-key navigation. When a filter combination matches nothing, cards simply vanish with no
"No titles match" message. The result count is not in an `aria-live` region, and renders `0`
before JS runs while eight cards are visible.

### 15. Localised catalogue slugs are not locale-consistent
`dist/en/catalogue/mathematiques-cm1/` and `dist/fr/catalogue/english-language-form-3/` both
exist — every title generates all eight slugs under both locales regardless of language. URLs
should be localised per locale, with redirects for the other form.

### 16. Nine ad-hoc breakpoints
`global.css` uses `max-width` at 1080, 900, 860, 800, 768, 700, 560, 520, 380. Promote three or
four to named tokens; the rest are per-component patches that will drift.

### 17. Two parallel design systems
`global.css` (burgundy `#5C1A2B`, green `#6FBF3F`) and `AdminLayout.astro` (wine `#641d36`, gold
`#d6a64b`, green `#257a5a`, ink `#1e2434`) define different palettes for the same brand. The
admin is a client-facing product for their editorial team; it should look like Longhorn.

### 18. Language switcher is visually-only
`src/components/Header.astro:38-51` — active locale is indicated by background colour alone. Add
`aria-current="true"` and `hreflang`/`lang` attributes so screen-reader users know which language
they are in and what the other link leads to.

### 19. Homepage has no social proof
Five sections, no testimonials, no client/institution logos, no news teaser — despite a working
news CMS. For an institutional-sales site, third-party credibility is the highest-leverage
missing block.

### 20. News is built but not connected
The admin publishes news; `/en/news/` and `/fr/news/` render a hardcoded "coming soon" empty
state. The pipeline is half-wired.

2. **Days 3–7 — Accessibility floor.** Items 4, 5, 7, 8, 13, 18. Non-negotiable for a publisher

fix is applied to a string-replacement layer that will keep leaking English into French.
