### Cleanup-path failure analysis (no further delete attempted)

- **Affected UI routes:** `/admin/news/` and `/admin/catalogue/`. Both remain on the admin route
  after selecting the exact Dell-labelled Delete control; no login redirect, server error, or CMS
  status text was observed. A later list reload still showed the news draft, so no delete request
  completed.
- **Observed automation failure:** selecting Delete opens the page's native `confirm()` dialog.
  The browser driver then reports `Timed out after 1577ms waiting for CDP command
  Input.dispatchMouseEvent` (a repeat through DOM control timed out after 2985ms). It next reports
  `A confirm JavaScript dialog is active in this tab`. Calling the supported dialog-accept method
  then timed out and reset the browser session (`js execution timed out; kernel reset`). This is a
  browser-automation/dialog-handling failure, not evidence of an application redirect or API
  rejection.
- **Supported record-delete API:** `DELETE /api/news-admin?id=<record-id>` and
  `DELETE /api/catalogue-admin?id=<record-id>` are protected by `requireAdmin()` and delete exactly
  the specified record. They return `{ deleted: id }`; a draft deletion does not request a rebuild.
  They can safely complete record cleanup only from a request authenticated as an Identity user with
  the `admin` role. QA cannot safely manufacture or extract that session credential outside the
  browser.
- **Media gap:** `/api/media` implements only authenticated `POST` and `GET`; it has no delete
  route. Therefore the authenticated CMS API alone cannot clean up the orphaned test blob. After
  the catalogue row is deleted, the supported scoped cleanup is
  `netlify blobs:delete longhorn-media uploads/30cb2749-2307-4b19-87a7-8d45eb1e2c2d.jpeg`, followed
  by `netlify blobs:list longhorn-media --json` and anonymous direct/CDN `404` verification.
- **Repair scope:** make the native confirmation reliably operable by the supported test surface,
  or add an authenticated admin media-delete endpoint/UI that rejects blobs still referenced by
  published or draft content. Do not add a broad database/blob deletion workaround.
