### Findings (fix list)

- **A-1 — Label in Name fails (WCAG 2.5.3, Level A), every admin page.** "Open Site" has `aria-label="Open public website in a new tab"`, and the search button shows "Search pages…" but is named "Search admin pages". The visible text is not contained in the accessible name, so voice-control users saying "click Open Site" or "click Search pages" fail. Fix: `aria-label="Open Site (opens in a new tab)"`, or visible text plus visually-hidden suffix; drop the `aria-label` on search or make it begin with "Search pages".
- **A-2 — Focus is lost on login state changes (WCAG 2.4.3).** Activating "Forgot your password?" leaves `document.activeElement` on `<body>` at all 7 viewports; "Back to sign in" uses the same hide-the-form pattern (by code, not exercised). After a failed sign-in the submit button is disabled during the request and focus also ends on `<body>`. Fix: move focus to the new form's first field (or the `h1` with `tabindex=-1`), and use `aria-disabled` or restore focus after the request.
- **A-3 — Login errors are polite, not alert, and not tied to fields (WCAG 4.1.3, 3.3.1; spec §7).** `#status` is `role="status" aria-live="polite"` for failures such as "Invalid email or password"; "Passwords do not match" neither focuses nor marks the confirmation input (`aria-invalid`, `aria-describedby`). Non-401 failures surface the library's raw message (a mocked 404 showed "Not Found").
- **A-4 — Unicode arrow in login buttons.** Accessible names read "Sign in →", "Send recovery link →", "Activate administrator account →", "Set new password →". Spec §2 asks for the shared SVG icon, `aria-hidden`.
- **A-5 — Targets under 44px.** Brand/logo link is 36px tall on every admin page and on login. Dashboard panel header links "Manage slides" and "View catalogue" are 22px tall (spec §5: trailing link min-height 44px). The dashboard section-status row links have no `min-height` either (rendered by script, so not measured here).
- **A-6 — Heading and landmark polish (low).** The four nav group labels are `<h2>` and come before the page `h1`, so heading navigation lists Workspace, Website, Content, Settings as page sections. The `<aside>` is an unlabeled complementary landmark, and the nav and the drawer dialog share the name "Admin navigation".
- **A-7 — Dashboard runtime risks, from code review, unconfirmed (need authenticated or fault-injection run).** `render()` runs on every source settle and does `errorBox.replaceChildren()`, rebuilding every `role="alert"` card each time. With N failed reads (expired session or API outage means up to 11), alerts are re-inserted about N times each, so announcements repeat (spec: alert once). The same rebuild destroys a focused **Retry** button on click, and **Refresh** disables itself while loading, so focus drops to `<body>` in both cases. `src/pages/admin/index.astro` lines 93–94 and 97–105.
- **A-8 — Public stylesheet is not byte-identical (info).** `Layout.*.css` and `404.*.css` get new hashes because Tailwind scans admin sources: `.sr-only`, `.m-4`, `.uppercase` and `--spacing` are added; `.flex-shrink`, `.backdrop-filter`, `.ease-in-out` and `--ease-in-out` are removed. No public template, script or style uses any of those (grepped), so no visual or behavioural change is expected. It does mean public CSS URLs change on the next deploy. SSR HTML was not rendered, so this is a build-output and source comparison, not a rendered one.
- **A-9 — Login polish (low).** No required marker or legend on the four forms (the editors get theirs from `admin-presentation.ts`, which login does not load). The password placeholder is a string of bullet characters.
- **A-10 — Drawer safe area (low, unconfirmed).** `.sidebar.in-drawer` is `height: 100dvh` inside `.admin-drawer` (`height: 100dvh`, safe-area padding, `overflow: hidden`), so on notched phones the bottom of the account card may clip by the inset. `env()` is 0 in desktop Chromium, so this needs a real device or preview.
